# joe Linux ARM package recipes

The recipe format is joe Linux's (this file is its recipe reference, with the
differences joe Linux ARM makes noted where they apply). In short, what is
different here:

- The C library is **bionic** (`packages/bionic`), the toolchain **LLVM**:
  `cc`, `c++`, `ld`, `ar`, `nm`, `strip` and the rest are clang, lld and
  LLVM's tools, the cross toolchain in `/usr/lib/joe-cross`, first in `PATH`
  in every build (`packages/.build/driver.sh`). There is no GCC or binutils.
  A library a C++ program needs at run time is `llvm-runtimes` (libc++), in
  place of `gcc`'s libstdc++.
- The build root is aarch64 and runs under qemu-user: configure scripts and
  build tools run as on the target, slower; compiling runs at the build
  machine's speed. Never use `-march=native` or let a build pick it: in the
  build root it would mean the build machine's processor.
- Where a package fails because bionic is not glibc, first ask whether bionic
  is what differs from a Linux C library; if so the fix is a patch to bionic
  (`packages/bionic/patches`), not to the package.
- There is no systemd. Services are dynamod's: a package ships
  `usr/lib/dynamod/services/NAME.toml` (see dynamod's docs/configuration.md),
  off by default for optional servers (`enabled = false`). `sysusers.d` and
  `tmpfiles.d` files work as before: dynamod provides `systemd-sysusers` and
  `systemd-tmpfiles`.
- Authentication goes through Linux-PAM, as in joe Linux.

One directory per package. Each holds two files.

## `package.zon`

```zon
.{
    .name = "zlib",
    .version = "1.4",            // upstream version, exactly as upstream writes it
    .release = 1,                // bump when the recipe changes
    .description = "One line, no trailing full stop",
    .license = "SPDX expression",
    .sources = .{
        // The first source is unpacked automatically. Later ones (patches,
        // extra tarballs) are available as $SOURCES/<file name>.
        .{ .url = "https://...", .sha256 = "<64 hex digits>" },
    },
    .depends = .{ "glibc", "zstd >=1.5" },   // needed at run time
    .build_depends = .{ "meson" },           // needed only to build
}
```

`.file = "name"` on a source overrides the file name taken from the URL.

A source whose URL is `git+URL#COMMIT` is that commit of a git repository,
as the tar file `git archive` makes of it (with a top directory `src/`); its
`.file` must be given and its `.sha256` is that of the tar. Use it where the
host's own archives are not reproducible (AOSP's are made on every request).

`.build_only = true` keeps a package out of the build root: it is built and
published, but nothing later builds against it. Packages that only assemble
others (`joe-desktop`) say this.

`.network = true` lets the build reach the network. Builds are offline by
default; the exception is for build systems that fetch their own dependencies
(cargo, go, cabal, npm and yarn, Maven), and every use of it is a debt to be
paid by vendoring.

`.conflicts = .{ "inetutils <2.8-r4" }` keeps the package from being installed
beside those versions of another. Use it when a file moves from one package
to another: the resolver then upgrades the old owner in the same transaction,
so the two are never installed with the same file.

The build order is computed from `depends` and `build_depends`
(`bootstrap/order.py`), so both must be complete: a library a package links
against belongs in `depends`, a tool it only runs while building in
`build_depends`. The base system is the exception; its order is `ORDER`.

### Privileged operations

`.operations` declares what the package's programs may do when privileged:

```zon
.operations = .{
    .{ .programs = .{"usr/bin/mount"}, .allow = .{ "mount", "cap:sys_admin" } },
    .{ .allow = .{"none"} },
},
```

The first entry naming a program wins. An entry with no `programs` is the
package default. `none` is an explicitly empty policy. Other operations are
`all`, `net`, `root-ipc`, `mount`, `module`, `ptrace`, `bpf`, `cap:NAME`,
`write:/absolute/prefix`, and `exec:/absolute/program`; `cap:*`, `write:*` and
`exec:*` mean any. Use `all` only for a reviewed general-purpose program.

A file no entry covers is sealed `undeclared`, which is generated by dave and
is not valid in a recipe. It has no authority of its own: an `all` caller passes
`all` to it, while another caller reports and, when enforcing, refuses it.
`dave repo audit build/repo` lists undeclared privileged programs and invalid
or missing seals. Keep that audit clean.

## `build.sh`

A bash file defining functions. It is sourced, not executed, so it must not run
anything at top level.

| Function  | Default            | Purpose                                   |
|-----------|--------------------|-------------------------------------------|
| `unpack`  | extract first source, stripping its top directory | rarely overridden |
| `prepare` | nothing            | patches, fixes to the source              |
| `build`   | nothing            | configure and compile                     |
| `package` | required           | install into `$DESTDIR`                   |

All four run in the unpacked source directory, as root in a user namespace,
inside the build root, with no network unless the recipe says `.network =
true`. Any command that fails aborts the build.

Available variables: `DESTDIR`, `SOURCES`, `PKG_NAME`, `PKG_VERSION`,
`PKG_RELEASE`, `JOBS`. `MAKEFLAGS` is already set to `-j$JOBS`.

`PKG_VERSION` is the upstream `.version`; `PKG_RELEASE` is the full
`VERSION-rN` string. Use `PKG_RELEASE` directly for distro build identifiers
(for example SBAT), without adding another version or `-r` prefix.

## Writing a recipe from the book

Recipes follow Linux From Scratch and Beyond LFS (systemd, development
branch). `packages/.build/book.py` prints a page's commands, and for Beyond LFS
also its download locations, checksums and dependency lists:

    packages/.build/book.py chapter08/zlib
    packages/.build/book.py --blfs general/glib2

The book installs into the running system; a recipe stages into `$DESTDIR`:

- `make install` becomes `make DESTDIR="$DESTDIR" install`; meson,
  `DESTDIR="$DESTDIR" ninja install`; cmake, `DESTDIR="$DESTDIR" cmake --install
  build`. Check that the package honours `DESTDIR`.
- Every later command that touches installed paths (`mv`, `ln`, `rm`,
  `install`, `sed -i`, `chmod`) acts on `"$DESTDIR/..."`. A symlink's target
  stays as the book wrote it; only its location gets the prefix.
- Source edits and patches go in `prepare`, configuring and compiling in
  `build`, installing in `package`.
- Leave out: test suites, `ldconfig`, cache updates
  (`glib-compile-schemas`, `gtk-update-icon-cache`, `update-mime-database`,
  `update-desktop-database`, `fc-cache`, `gio-querymodules`), documentation-only
  steps, account creation, and "move the old version away" steps. Caches are
  rebuilt by triggers shipped by the package that owns the tool.
- Default configuration the book writes with a heredoc is installed under
  `$DESTDIR/etc`.
- Use the versions, URLs and flags on the page, not remembered ones: these
  are development-branch books. Download each source into `build/src/`, check
  it against the MD5 the page gives, and record its SHA-256.
- Enable an optional feature only if what it needs has a recipe; otherwise
  switch the feature off explicitly, so the result does not depend on what
  happens to be in the build root.

A recipe directory is claimed by creating it. If `packages/NAME` already
exists, someone else is writing that recipe.

## Rules

- **Everything goes through `$DESTDIR`.** Never write to `/usr`, `/etc` and so
  on directly: the build root is shared by every build.
- Install under `/usr`. `/bin`, `/sbin` and `/lib` are symlinks to `usr/bin`,
  `usr/sbin` and `usr/lib`, owned by `joe-filesystem`; a package must never
  contain a path starting with `bin/`, `sbin/` or `lib/`. Libraries go in
  `/usr/lib` (never `lib64`): pass `--libdir=/usr/lib` where upstream would
  choose otherwise.
- Files are owned by root. Never `chown` or `chgrp` to anything else and never
  call `setcap`; ownership other than root is set up at run time by
  `sysusers.d` and `tmpfiles.d`. Set-uid is fine: `chmod 4755`.
- Nothing under `/var`, `/run` or `/tmp` is packaged (the driver removes it):
  `/var` is shared between deployments and the other two are temporary. Ship a
  `usr/lib/tmpfiles.d/NAME.conf` for anything that must exist there.
- A daemon that runs as its own user ships `usr/lib/sysusers.d/NAME.conf`
  giving that user and group a **fixed** id (`u gdm 21 "GNOME Display Manager"
  /var/lib/gdm`). Ids must be the same on every machine and in every
  deployment because `/var` is shared between deployments. Files that must
  belong to that user are created at boot by `tmpfiles.d`, never packaged.
- No install scripts exist. If something must run after installation (a cache
  rebuild), ship a trigger in `usr/lib/dave/triggers/NAME.zon`:
  `.{ .paths = .{"usr/lib/"}, .exec = .{"/usr/bin/ldconfig"} }`.
- Do not run test suites.
- Do not strip, delete `.la` files or remove `usr/share/doc`,
  `usr/share/info` and `usr/share/gtk-doc/html` yourself; the build driver
  does that for every package. Set `NOSTRIP=1` at the top of `build.sh` to
  keep symbols.
- Ship Python byte code as the build compiles it. The driver rewrites every
  `__pycache__/*.pyc` to check a hash of its source (PEP 552) instead of a
  modification time, which dave does not keep, so it stays valid on installed
  systems and a privileged Python never writes unsealed byte code of its own.
- Static libraries are not shipped unless something needs them.
